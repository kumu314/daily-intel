# 一手情报数据库 & 每日交叉分析

只存一手事实，不存二手解读。事实与判断物理隔离，判断错了可以改，事实永远是事实。

## 目录

```
intel/
├── db/
│   ├── schema.sql        四张表：fact(事实) metric(指标) cross_note(联动) ocean(红蓝海)
│   └── intel.db          SQLite 数据库（自动创建）
├── data/
│   └── 2026-08-31.json   每天一份，当天的事实 + 指标 + 分析，这是唯一需要新增的文件
├── reports/
│   └── 2026-08-31.html   生成的单页可视化报告
├── init_db.py            建库（幂等）
├── ingest.py             把 data/*.json 灌进数据库
├── query.py              检索与回溯
├── verify.py             验尸台（本系统最重要的一个脚本）
└── report.py             生成 HTML 报告
```

## 每天怎么做

```bash
# 1. 复制昨天的 JSON，改名成今天
# 2. 往里面填今天的一手事实（facts）、数字（metrics）、判断（analysis）
# 3. 跑三条命令
python ingest.py        # 入库
python report.py        # 出报告
python query.py 关键词   # 想回溯历史时查
```

## 六个维度，缺一不可

| 维度 | 一手来源 |
|---|---|
| 政策 | 国务院常务会议、国新办发布会、各部委官网 |
| 宏观 | 国家统计局、央行、财政部、教育部 |
| 市场 | 交易所行情、Wind、券商策略、ETF 申赎 |
| 国际 | 美联储、BLS/BEA、IEA、路透/新华社 |
| 产业 | 行业协会、企业公告、工信部 |
| 舆论 | 平台热搜、网信办通报、权威媒体复盘 |

`tier` 字段标来源等级：1 = 官方原始发布，2 = 官方媒体/交易所，3 = 行业权威机构。**不要收录 tier 3 以下的自媒体观点。**

## 三条铁律

1. **事实必须有出处和链接**，没有出处的一律不进库。
2. **判断必须写明传导链条**，不能只说"利好""利空"，要说清 A 怎么传导到 B。
3. **每天至少更新一条 watchlist**，注明下一个变量几月几日到来——情报的价值在提前量。

## 三条纪律（第一版自评后立的，写在 report.py 文件头）

1. **不同性质的数字，绝不用同一张图比大小。**
   通胀只能跟通胀比，利率只能跟利率比，行业不能跟指数混排。否则就是制造错觉。

2. **主观打分必须写明「这是估计，不是数据」。**
   别把拍脑袋的判断画成进度条——图表会给猜测背书，让猜测看起来像测量。

3. **每条判断后面必须跟一条翻车线。**
   写明"什么情况出现，就说明我说错了"。没有翻车线的判断等于算命，而且很滑头：说对了是功劳，说错了数据会变，永远不亏。

## 事实分级

| 级别 | 含义 | 展示方式 |
|---|---|---|
| 1 | 必须知道 | 正文，红色标签 |
| 2 | 值得知道 | 正文，蓝色标签 |
| 3 | 存档备查 | 折叠，不占正文 |

每天的分级控制在 4 条 / 8 条 / 其余。分级错了可以随时改 JSON 里的 `level`。

## 文风要求

写给普通人看，不写给同行看。

- 短句，一句话不超过二十个字
- 不写术语。"重新定价""政策空间""周期分岔"这类词一律翻译成大白话
- 数字用中文念法（"百分之一点四一"，不是"1.41%"）
- 事实照抄数字，删掉所有官方定性形容词（"总体平稳""彰显韧性"这类）
- 每篇结尾要有一句能让人记住的话

## 检索示例

```bash
python query.py                      # 库存概览
python query.py 霍尔木兹              # 全文搜索
python query.py --dim 国际 --last 7   # 某维度最近 7 天
python query.py --name "LPR 1Y"      # 某指标历史序列
```

## 验尸机制（这套系统的核心）

前面所有环节——抓事实、入库、画图、出报告——都是在为这一节服务。

**判断谁都会下。难的是到期之后，老老实实回来看自己错了几条。**

每条判断存进 `call` 表时必须带三个东西：判断原文、翻车线、到期日。到期后用 `verify.py` 记录结果：

```bash
python verify.py                 # 列出全部判断，按到期日排序
python verify.py --overdue       # 只看已到期、还没验的
python verify.py --due 2026-09-04
python verify.py --hit 3         # 第 3 条：没翻车
python verify.py --miss 3 --note "非农只掉 1 万，没到门槛，但方向也判错了"
python verify.py --stat          # 命中率
```

规则：

- **没写翻车线的判断不进 `call` 表。** 不可证伪的东西不配叫判断。
- **翻车线必须可判定。** 写"先核实真假"这种不算，要有日期、阈值、后果。
- **已验过尸的记录不会被重新导入冲掉。** 重复跑 `ingest.py` 只清掉 pending 的。
- **命中率低于 50% 就该改方法了**——那说明这套分析不如扔硬币。

### 翻车线怎么写才算数

| 不合格 | 合格 |
|---|---|
| 要是真看到同行月入过万，先核实真假 | 三个月内，小红书上做 AI 测评的账号里，你能亲眼看到超过 3 个粉丝不到一万却稳定接广告的 |
| 市场可能变化 | A 股单日成交额连续 5 天站上 2.5 万亿、且上证站上 4200 点 |
| 政策可能转向 | 9 月社融增速回到 8% 以上、PMI 站上 50 |

差别在于：**合格的翻车线，到了那天你自己就知道该打勾还是打叉，不需要再争论。**
